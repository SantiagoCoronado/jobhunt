## Runbook for the three harness runs

### Once, on the new machine (macOS; on Windows, run all of it inside WSL)

1. Tools: `brew install python@3.12 node gh` and `brew install --cask libreoffice` (stop 4).
2. GitHub, since the repo is private: `gh auth login`.
3. The three CLIs: `npm install -g @anthropic-ai/claude-code @openai/codex
   @earendil-works/pi-coding-agent`, then sign in to each: `claude` (then `/login`),
   `codex login`, and pi the way the old machine had it (an OpenRouter key there).
4. Bring the documents, which no clone carries (git-ignored): the CVs from
   `resume/originals/`, the LinkedIn "Save to PDF" or data-export zip if wanted. Put them in
   one folder, say `~/cvs/`. Source keys (adzuna and the rest) are optional; the interview
   asks, and "skip" is fine.

### Each run (claude, then codex, then pi), a fresh clone each

1. Clone the branch and install for one harness:
   ```
   cd "$(mktemp -d)" && gh repo clone jobhunt -- -b test/full-flow && cd jobhunt   # gh fills in your account
   ./setup.sh --harness claude        # codex in the second clone, pi in the third
   ```
2. codex and pi only, until stop 5 is fixed: clear the claude model names so each stage takes
   the harness default, then check:
   ```
   .venv/bin/python -c "from src.hunt import config as c; [c.set_stage_model(s, None) for s in ('triage','match','inbox','research','tailor')]"
   .venv/bin/python -m src.hunt doctor      # must end with "result: ok"
   ```
3. Optional, to keep it cheap: research and tailor one job instead of five:
   `sed -i '' 's/^n = 5/n = 1/' config/hunt.toml` (the `[pick]` block).
4. Open the CLI in the clone and run the interview on the documents:
   claude and pi: `/jh-setup ~/cvs/<file>.pdf ~/cvs/<file>.docx`; codex: type
   `jh-setup ~/cvs/<file>.pdf ~/cvs/<file>.docx` (codex reads the flows from `AGENTS.md`).
   Answer its questions; skip mail.
5. Same session: `/jh-hunt` (codex: `jh-hunt`). Let it run until it ends; the run is done
   when a folder lands in `applications/pending/`.
6. Keep notes as it goes: what you typed, where it stopped, anything you had to work out
   that the screen did not say.
7. Send the dev session the notes and the output of `.venv/bin/python -m src.hunt report
   latest` (the tokens per stage). Each run becomes a section below, each stop a commit on
   this branch; push, and the next clone has the fix.
